# 代码审查技能

## 适用场景

- 用户明确要求进行代码审查或安全审计。
- 刚完成一项功能实现或问题修复。
- 准备建议提交代码或创建合并请求。

## 审查清单

### 1. 正确性

- 是否处理空输入、空值和较大数值等边界情况？
- 是否覆盖错误分支，异常是否得到妥善处理？
- 循环或切片是否存在边界偏移错误？

### 2. 安全性

- 是否对用户输入进行了校验和必要的清理？
- 是否将密钥或 API 密钥硬编码在代码中？如有，应明确指出。
- 文件操作是否存在路径遍历风险？
- 命令执行是否使用了不可信输入？

### 3. 风格与可读性

- 命名和格式是否与周边代码保持一致？
- 变量和函数名称是否清楚表达用途？
- 注释是否解释了实现原因和设计取舍？
- 是否存在应当删除的无效代码或已注释的旧代码块？

### 4. 性能

- 处理大型集合时是否使用了 O(n²) 算法？
- 是否在循环中重复获取相同数据？
- 是否适合使用列表推导式或生成器简化循环？

### 5. 测试覆盖

- 是否测试了正常流程和至少一种错误流程？
- 是否为本次修复的问题提供了针对性测试？

## 输出格式

```
## 代码审查 —— {文件或功能}

### 发现的问题（按严重程度排序）

1. **高风险** —— {问题描述}
   - 文件：{路径}:{行号}
   - 建议：{修复方式}

2. **中风险** —— ……

### 审查摘要

共 {问题数量} 项：高风险 {高风险数量} 项，中风险 {中风险数量} 项，低风险 {低风险数量} 项。
```
